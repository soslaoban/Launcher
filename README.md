# 启动器（Launcher）项目文档

## 1. 项目概述

启动器是一款面向 Windows 的本地桌面应用，用于集中管理并快速启动电脑上的 `.exe` 应用。它提供类似 ChatGPT 的双栏布局：左侧是分类与筛选，右侧是当前分类下的应用列表，用户可以通过搜索、收藏或最近使用记录快速找到目标应用。

本项目首先服务于“我安装了很多应用，但启动入口分散、难以查找”的场景。它不替代 Windows 的文件管理器，也不移动、复制或卸载用户的应用文件；启动器只保存应用路径和启动配置，并调用操作系统启动目标程序。

## 2. 产品目标

- 在一个简洁、清晰的界面中管理所有常用 `.exe` 应用。
- 添加应用后，一键启动，启动反馈明确且可追踪。
- 通过分类、搜索、收藏和最近使用降低查找成本。
- 对路径失效、权限不足和启动失败给出可理解的提示与修复入口。
- 保持轻量、低资源占用，支持最小化到系统托盘。
- 所有数据默认保存在本机，不上传应用清单、路径或使用记录。

## 3. 用户与典型场景

### 3.1 目标用户

- 安装了较多工具、开发软件、设计软件或游戏的 Windows 用户。
- 需要按工作场景组织程序入口的个人用户。
- 希望使用便携版软件，但不想为每个软件创建桌面快捷方式的用户。

### 3.2 典型流程

1. 用户首次打开启动器，看到空状态和“添加应用”按钮。
2. 通过文件选择器、拖拽 `.exe` 文件或扫描指定目录添加应用。
3. 为应用选择分类、设置显示名称和可选启动参数。
4. 在分类列表中浏览，或使用全局搜索定位应用。
5. 点击应用卡片启动；启动器记录最近使用时间和次数。
6. 用户可以编辑、复制启动配置、收藏、移动分类或删除记录。

## 4. 功能范围

### 4.1 首版（MVP）必须功能

#### 应用管理

- 添加 `.exe` 应用：文件选择器、拖拽添加。
- 删除应用记录：二次确认；仅删除启动器记录，不删除磁盘上的 exe 文件。
- 编辑应用：名称、图标、分类、启动参数、工作目录、备注。
- 从资源管理器打开所在目录。
- 手动重新选择目标文件，修复失效路径。
- 启动应用：调用 Windows 原生进程启动能力。
- 启动状态提示：启动中、已启动、路径不存在、权限不足、启动失败。

#### 分类与浏览

- 内置分类：全部、最近使用、收藏；用户可新建、重命名、删除自定义分类。
- 一个应用可归属一个主分类，并支持收藏标记。
- 分类侧栏显示应用数量。
- 右侧应用卡片网格/列表视图（首版默认为网格，支持切换为紧凑列表）。
- 空分类和无搜索结果提供明确空状态。

#### 搜索与排序

- 全局实时搜索：匹配应用名称、路径、备注和启动参数。
- 排序选项：名称、最近使用、使用次数、添加时间。
- 搜索快捷键 `Ctrl/Cmd + K`，回车启动首个匹配项。

#### 数据与可靠性

- 应用配置持久化到本地 JSON/SQLite 数据库。
- 应用唯一标识使用稳定 ID；路径使用规范化后的绝对路径。
- 启动器启动时检查路径有效性并标记失效项，不静默删除。
- 数据导出与导入（JSON），便于备份和迁移。
- 发生错误时保留日志，设置页提供“打开日志目录”。

#### 外观个性化

- 预置主题：跟随系统、浅色、深色、二次元、赛博朋克。
- 自定义背景：选择本地图片（PNG/JPG/WebP），支持纯色背景；默认只保存本地文件路径。
- 背景显示方式：填充、适应、居中、平铺；支持背景透明度、遮罩强度和模糊程度调节。
- 主题设置即时预览，点击“恢复默认”可一键撤销当前外观修改。
- 主题只影响颜色、字体、背景、边框、阴影和装饰元素，不改变核心功能、快捷键和数据结构。

### 4.2 建议纳入首个可用版本的增强功能

- 扫描用户选择的目录，批量发现 `.exe`，由用户勾选后导入。
- 自动读取 Windows 可执行文件图标；读取失败时使用统一的默认图标。
- 支持自定义图标图片（PNG/ICO），并生成缩略图缓存。
- 启动参数模板和环境变量输入。
- 应用卡片快捷菜单：启动、编辑、复制、移动分类、打开目录、删除。
- 系统托盘常驻、全局唤起快捷键、开机启动开关。
- 主题：跟随系统、浅色、深色；支持紧凑/舒适显示密度。
- 应用启动历史与失败原因（默认只保留最近 50 条）。
- 主题编辑器：自定义强调色、圆角、背景遮罩、卡片透明度和界面密度，并支持保存为个人主题。
- 主题包导入/导出：使用版本化 JSON 描述主题，图片资源单独存放并校验大小和格式。

### 4.3 后续版本候选功能

- 自定义命令/脚本入口（PowerShell、批处理、URL），与 exe 使用统一卡片模型。
- 多配置档案，例如“工作”“游戏”“演示”。
- 应用分组拖拽排序和键盘导航。
- 便携模式：将数据库放在启动器目录，随程序一起迁移。
- 多语言支持。
- 自动检测应用版本或路径变化（需明确权限和隐私策略）。
- 在线主题市场或主题分享（仅在建立资源审核、版权和隐私机制后考虑）。

### 5.2 视觉原则

- 默认采用中性背景、清晰层级和克制的强调色；个性化主题可以更具表现力，但不能牺牲文字可读性和操作反馈。
- 侧栏宽度稳定，右侧内容区自适应；窗口最小尺寸建议 `960 × 640`。
- 应用卡片圆角不超过 8px，图标尺寸统一，名称最多显示两行。
- 所有图标按钮提供悬停提示，关键操作保留文字和图标。
- 颜色不能成为唯一状态提示；失效路径同时显示图标、文字和操作按钮。
- 支持键盘：`Ctrl/Cmd + K` 搜索、方向键移动、回车启动、`Delete` 删除（需确认）、`Esc` 关闭弹窗。

### 5.3 主题与背景设计

#### 主题类型

| 主题 | 视觉方向 | 设计约束 |
| --- | --- | --- |
| 跟随系统 | 根据 Windows 设置自动切换浅色/深色 | 不覆盖系统级高对比度设置 |
| 浅色 | 明亮、低饱和、适合办公 | 保证正文与背景达到可读对比度 |
| 深色 | 深灰底色、低眩光 | 不使用纯黑大面积铺底 |
| 二次元 | 插画背景、柔和或糖果色强调色、轻量装饰 | 背景必须可调暗；不使用影响文字识别的大面积动态动画 |
| 赛博朋克 | 深色底、青色/品红色强调、细线和网格装饰 | 霓虹色只用于强调，不让发光效果覆盖正文和按钮文字 |

#### 背景设置

- 背景图片显示在内容区域底层，侧栏和卡片使用主题遮罩保证层级清晰。
- 支持静态图片；首版不支持视频背景和联网实时壁纸，避免资源占用、隐私和稳定性问题。
- 加载图片时显示占位背景；图片读取失败自动回退到主题默认背景，并提供重新选择入口。
- 图片路径失效时保留主题配置并标记“背景不可用”，不能导致启动器白屏。
- 图片文件建议不超过 10 MB，超出时提示压缩或选择其他图片。

#### 主题编辑器

- 设置页分为“预置主题”“背景”“颜色与效果”“预览”四个区域。
- 预览区域使用真实侧栏、应用卡片和弹窗示例，避免只展示色块。
- 可编辑项至少包括：强调色、背景遮罩、卡片透明度、边框亮度、圆角、阴影强度和显示密度。
- 提供恢复默认、复制主题和删除个人主题；当前正在使用的主题不可直接删除。
- 动效提供关闭开关，并尊重 Windows 的减少动态效果设置。

### 5.4 关键交互

- **添加应用**：选择 exe 后打开编辑弹窗；默认名称取文件名，默认分类为“未分类”。保存前校验扩展名、路径存在性和可执行权限。
- **删除应用**：确认弹窗必须明确“只删除启动器记录，不删除文件”。
- **启动应用**：点击卡片主体或“启动”按钮均可；启动后按钮短暂显示状态，失败时显示可复制的错误详情。
- **失效应用**：卡片置灰但仍可编辑；提供“重新定位”和“从列表移除”。
- **批量扫描**：扫描结果先进入待确认列表，不自动写入数据库。
- **切换主题**：选择预置主题后即时生效并自动保存；若资源加载失败，显示原因并回退到可用主题。
- **更换背景**：文件选择器只展示支持的图片格式；保存后立即预览，取消则恢复上一次配置。
- **编辑主题**：所有滑块和颜色选择器都有数值/文字反馈；对比度不足时给出提示，但不阻止用户保存自定义主题。

## 6. 技术方案

### 6.1 推荐技术栈

- **桌面容器**：Tauri 2（Rust 后端，体积和资源占用较小）。
- **前端**：React + TypeScript + Vite。
- **UI**：CSS Modules 或项目内 CSS 变量；图标使用 Lucide。
- **数据存储**：SQLite（通过 Rust 侧访问）；小规模实现也可先使用版本化 JSON，需保留迁移接口。
- **进程启动**：Tauri/Rust 命令调用 Windows 原生进程 API，前端不直接拼接 shell 命令。
- **测试**：Vitest（前端逻辑）、Rust 单元测试、Playwright（关键界面流程）。
- **打包**：Windows NSIS 安装包，后续可增加便携 ZIP。

### 6.2 分层结构

```text
React UI
  ├─ 状态层（应用、分类、搜索、设置、主题）
  ├─ Tauri invoke API（类型化命令）
  └─ 组件层（侧栏、工具栏、应用卡片、弹窗、主题编辑器）
Rust Core
  ├─ Repository（SQLite/JSON 与迁移）
  ├─ Launcher（路径校验、参数解析、进程启动）
  ├─ Scanner（目录扫描与图标读取）
  ├─ Theme Assets（背景文件校验、缩略图和缓存）
  └─ System Integration（托盘、开机启动、快捷键）
```

### 6.3 主题实现约定

- 使用 CSS 变量承载主题令牌，例如背景色、文本色、强调色、边框色、圆角和阴影；组件不得硬编码主题颜色。
- 主题定义包含 `schemaVersion`、令牌、背景配置和动效偏好，导入时必须校验版本、字段类型和可接受范围。
- 本地背景复制到应用数据目录的受控缓存中，原文件删除后仍可显示；导出主题时明确是否包含背景文件。
- 主题资源不加载远程脚本、不执行图片内嵌代码；导入主题包前校验压缩包大小、文件类型和路径穿越。
- 主题切换不应触发应用列表重新加载；背景缩略图和模糊效果使用缓存，避免滚动卡顿。

### 6.4 安全边界

- 仅允许启动经过用户明确添加或确认导入的目标路径。
- 启动前校验路径存在、扩展名为 `.exe`（大小写不敏感）且为普通文件。
- 启动参数作为参数数组传递，避免通过 shell 字符串执行，降低命令注入风险。
- 默认不请求管理员权限；需要提升权限时必须由用户主动操作并看到系统确认。
- 前端启用 Tauri 权限白名单和最小能力集，不开放任意文件系统访问。
- 日志中不记录敏感的完整参数（可按设置脱敏）。

## 7. 数据模型（初稿）

### Application

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | UUID，主键 |
| `name` | string | 展示名称 |
| `executablePath` | string | 规范化绝对路径 |
| `iconPath` | string/null | 缓存图标或自定义图标 |
| `categoryId` | string/null | 主分类 |
| `isFavorite` | boolean | 是否收藏 |
| `arguments` | string[] | 启动参数数组 |
| `workingDirectory` | string/null | 工作目录，默认 exe 所在目录 |
| `notes` | string | 备注 |
| `lastLaunchedAt` | datetime/null | 最近启动时间 |
| `launchCount` | integer | 启动次数 |
| `createdAt` / `updatedAt` | datetime | 创建和更新时间 |

### Category

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | UUID，主键 |
| `name` | string | 分类名称，唯一 |
| `sortOrder` | integer | 侧栏排序 |
| `createdAt` / `updatedAt` | datetime | 创建和更新时间 |

### ThemeProfile

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | UUID，主键 |
| `name` | string | 主题名称 |
| `preset` | string/null | 预置主题标识，如 `anime`、`cyberpunk` |
| `tokens` | object | 颜色、圆角、阴影、透明度等主题令牌 |
| `background` | object | 类型、路径、适配方式、遮罩、模糊参数 |
| `motionReduced` | boolean | 是否关闭非必要动效 |
| `createdAt` / `updatedAt` | datetime | 创建和更新时间 |

### UserSettings（或 Settings 表）

保存当前主题 ID、显示模式、启动器语言、托盘行为、开机启动、全局快捷键和默认分类等用户偏好。

### LaunchHistory（可选）

记录 `applicationId`、启动时间、结果（成功/失败）、错误码和简短错误信息；默认限制保留数量。

## 8. 非功能要求

- 冷启动目标：普通电脑上 2 秒内显示主界面。
- 空闲内存目标：不扫描时约 100 MB 以内，具体以实测为准。
- 主界面操作反馈目标：点击后 100 ms 内显示视觉反馈。
- 数据写入采用原子替换或事务，异常退出不得损坏已有配置。
- 窗口缩放、深色模式和高 DPI 显示下布局不重叠、不截断。
- 主题切换目标反馈时间不超过 100 ms（不含首次读取大图片）；背景加载过程不能阻塞主界面。
- 预置主题在常见窗口尺寸和高 DPI 下通过可读性检查；文字、图标和状态提示不能因背景导致不可辨认。
- 关闭动效后，主题切换、弹窗和启动反馈仍保留清晰的状态变化。
- 关键流程支持无鼠标键盘操作，控件具备可读的无障碍名称。

## 9. 开发阶段与验收标准

### 阶段 0：工程骨架

- 创建 Tauri + React + TypeScript 工程。
- 建立 lint、格式化、测试和 CI 基础配置。
- 验收：可在 Windows 本地启动开发模式并生成安装包。

### 阶段 1：MVP 主流程

- 分类侧栏、应用卡片、添加/编辑/删除、启动、搜索和本地持久化。
- 验收：用户可以添加 3 个 exe，分别分类，搜索并成功启动；删除记录不会删除 exe 文件；重启启动器后数据仍在。

### 阶段 2：可靠性与效率

- 失效路径修复、目录扫描、图标缓存、最近使用、收藏、排序、导入导出；预置主题、背景选择和基础主题设置。
- 验收：移动或删除 exe 后能显示失效状态；扫描结果不会未经确认自动导入；导出的 JSON 可在另一台机器上导入并逐项处理失效路径；切换二次元和赛博朋克主题后布局、文字和启动流程仍正常。

### 阶段 3：系统集成与发布

- 托盘、全局快捷键、开机启动、主题编辑器、主题包导入导出、日志和安装包签名准备。
- 验收：关闭主窗口后可从托盘唤回；快捷键可唤起；自定义主题和背景在重启后仍保持；失效背景能自动回退；安装、升级、卸载流程可完成。

## 10. 风险与决策记录

- **路径变化**：不尝试静默猜测新路径；优先提供重新定位，后续再考虑基于文件名和哈希的辅助匹配。
- **权限问题**：启动器不默认提权，避免造成不可预期的安全风险。
- **图标读取兼容性**：图标读取失败必须有默认图标，不能阻塞应用导入。
- **扫描性能**：目录扫描放在后台线程，显示进度并允许取消，禁止默认扫描整个系统盘。
- **存储格式演进**：从第一版就加入 schema/version 字段和迁移机制，避免未来数据无法读取。
- **删除语义**：产品文案统一使用“从启动器移除”，避免用户误以为会卸载应用。
- **视觉可读性**：个性化背景可能降低对比度；所有主题必须保留可调遮罩，并在预览和运行时提供可读性提示。
- **资源占用**：不采用视频背景作为首版能力；大图片使用缩略图、缓存和按需加载。

## 11. 暂不纳入范围

- 软件安装、卸载、自动更新和破解相关功能。
- 代替杀毒软件的安全扫描或信誉判定。
- 云端同步账号体系（除非后续明确需要，并重新评估隐私与安全）。
- 自动修改第三方应用注册表、快捷方式或安装目录。

## 12. 后续开发入口

实现阶段应先完成阶段 0，再按阶段 1 的主流程垂直切片交付。每个功能都需要同时补齐：界面状态、错误状态、键盘操作、持久化行为和对应测试；完成后再扩展系统集成功能。
